Hallym MIPS 2.4.0, the MIPS simulator for Hallym University's computer architecture labs. Your programs assemble and run exactly as in 2.3.0 (the same SPIM core).

## Download (Windows 64-bit)

One file: **`HallymMIPS-2.4.0-win-x64-setup.exe`**. Run it: it installs for you only (no administrator rights) and adds *Hallym MIPS* to the Start menu. If you have an earlier 2.x, it replaces it; the previous edition, 1.x ("Hallym MIPS Simulator"), is left as it is.

The program is not code-signed, so **Windows shows a blue "Windows protected your PC" window the first time. Click *More info*, then *Run anyway*** (Korean Windows: *추가 정보* → *실행*). Step by step: [한국어](https://github.com/ars2323/hallym-mips-simulator/blob/main/docs/usage/usage.ko.md#windows-경고-창-넘기기) · [English](https://github.com/ars2323/hallym-mips-simulator/blob/main/docs/usage/usage.en.md#getting-past-the-windows-warning).

## What you will see that is different

- **The installer tells you when it is done.** After the progress bar comes **설치가 완료되었습니다** (installation complete), with **지금 실행하기** (run now) ticked: click **마침** (Finish) and the program opens. It still asks nothing: it installs for you only, in the same place as before.
- **The start screen has the university's promotional video behind it**, without sound. If Windows' animation effects are turned off on your PC, it shows one still picture instead. Nothing changes once a file is open.
- **Export executable image (.hmx)**, a new button at the top right, saves the program you assembled as an `.hmx` file: its instruction words, its data, where it starts, and its labels. Hallym Circuit Studio loads it into a CPU you built there. If you changed the code since the last Ctrl+S, it saves the last assembled program, the one Run and Step use. The format is described in [hmx-format.md](https://github.com/ars2323/hallym-mips-simulator/blob/main/docs/hmx-format.md).

## Going back

If something is wrong with 2.4.0 on your PC, the earlier releases are still here:

- [2.3.0](https://github.com/ars2323/hallym-mips-simulator/releases/tag/v2.3.0): remove 2.4.0 first (Settings → Apps → Installed apps → *Hallym MIPS 2.4.0* → Uninstall), then install 2.3.0.
- [1.2.4](https://github.com/ars2323/hallym-mips-simulator/releases/tag/v1.2.4), the previous edition ("Hallym MIPS Simulator"): it installs beside 2.x, and the two do not touch each other.

## For maintainers: one check after the tag

The release rules (`CLAUDE.md`, "Releasing the Electron edition", rule 3) ask for the mutants to be killed before a release. For 2.4.0, one part of that runs after the tag, as an exception for this release only.

- **Before the tag.**
  - The whole set of 151 was killed at `v2.3.0`.
  - Every mutant's `find` still occurs exactly once in its file: all 169, text only. So the target code of the 87 mutants this round could not have touched has not moved; their `file` and `tests` are all outside the files changed since `v2.3.0`.
  - The 18 mutants added this round were each run and killed while they were written: 9 for the first screen's video, 9 for the `.hmx` image.
- **After the tag, on the tagged tree.** The 82 mutants this round could have touched run: those whose `file` or `tests` changed since `v2.3.0`, and the 18 added since.

The full pass was this release's bottleneck, and a killed mutant stays killed until its code or its tests change. If one survives, it is reported with the test it got past, and that test is made stronger in the next round. Only a real fault found by the stronger test would make a 2.4.1.
